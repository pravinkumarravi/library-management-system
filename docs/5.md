# 5. SYSTEM DESIGN

## 5.1 System Architecture

The application follows the classic **three-tier MVC architecture** of CodeIgniter:

```
┌──────────────────────────┐
│   PRESENTATION TIER      │  Browser → BladeOne views (HTML, Tailwind, Alpine, ApexCharts)
│   (Views / layouts)      │
└───────────┬──────────────┘
            │ HTTP request / response
┌───────────▼──────────────┐
│   APPLICATION TIER       │  CodeIgniter 3 controllers + models + libraries
│   (Controllers/Models)   │  Auth, Books, Categories, Members, Issues, Dashboard
└───────────┬──────────────┘
            │ SQL (Active Record)
┌───────────▼──────────────┐
│   DATA TIER              │  SQLite database (default) / MySQL schema
│   (Database)             │  users, categories, books, members, issues
└──────────────────────────┘
```

- **Controllers** handle requests, validate input and call models.
- **Models** encapsulate database queries using CodeIgniter's Active Record.
- **Views** are Blade templates rendered by the BladeOne library.
- **Libraries** include Blade, the Migration library and form validation.

## 5.2 Module Design

| Module | Controller | Responsibilities |
| --- | --- | --- |
| Authentication | `Auth` | Login, logout, session handling. |
| Dashboard | `Dashboard` | Aggregates counts and statistics; renders widgets and charts. |
| Books | `Books` | CRUD for books, search, copy count management. |
| Categories | `Categories` | CRUD for categories, book count per category. |
| Members | `Members` | CRUD for members, search. |
| Issues | `Issues` | Issue a book, return a book, overdue list, history. |
| Migration | `Migrate` (CLI) | Runs schema migrations from the command line. |

### 5.2.1 Issue / Return Workflow

```
Issue:
  Choose member → choose available book → set due date
  → available_copies - 1 → insert issues record (status = issued)

Return:
  Click Return on an issued row
  → available_copies + 1 → update issues record (status = returned, return_date)
  → fine recorded for overdue days (₹5/day)

Overdue detection:
  status = issued AND due_date < today
```

## 5.3 Database Design

The database contains **five tables**. The entity relationship is summarised below:

- **categories** `1 ──── *` **books** (a category has many books; a book has one category)
- **books** `1 ──── *` **issues** (a book can be issued many times)
- **members** `1 ──── *` **issues** (a member can borrow many times)

### 5.3.1 Table: users

| Column | Type | Notes |
| --- | --- | --- |
| id | INT (PK, auto) | Primary key |
| username | VARCHAR(80) | Login name, unique |
| password | VARCHAR(255) | Hashed password |
| name | VARCHAR(160) | Display name |
| created_at | DATETIME | Creation time |

### 5.3.2 Table: categories

| Column | Type | Notes |
| --- | --- | --- |
| id | INT (PK, auto) | Primary key |
| name | VARCHAR(120) | Category name |
| description | TEXT | Optional description |
| created_at | DATETIME | Creation time |

### 5.3.3 Table: books

| Column | Type | Notes |
| --- | --- | --- |
| id | INT (PK, auto) | Primary key |
| title | VARCHAR(255) | Book title |
| author | VARCHAR(255) | Author name |
| isbn | VARCHAR(40) | ISBN number |
| publisher | VARCHAR(160) | Publisher |
| year | INT(4) | Publication year |
| category_id | INT (FK) | Reference to categories.id |
| total_copies | INT | Total copies owned |
| available_copies | INT | Copies currently available |
| created_at | DATETIME | Creation time |

### 5.3.4 Table: members

| Column | Type | Notes |
| --- | --- | --- |
| id | INT (PK, auto) | Primary key |
| name | VARCHAR(160) | Member name |
| email | VARCHAR(160) | Email address |
| phone | VARCHAR(40) | Phone number |
| address | TEXT | Address |
| membership_date | DATE | Date of membership |
| status | VARCHAR(20) | active / inactive |
| created_at | DATETIME | Creation time |

### 5.3.5 Table: issues

| Column | Type | Notes |
| --- | --- | --- |
| id | INT (PK, auto) | Primary key |
| book_id | INT (FK) | Reference to books.id |
| member_id | INT (FK) | Reference to members.id |
| issue_date | DATE | Date the book was issued |
| due_date | DATE | Date the book must be returned |
| return_date | DATE | Date actually returned (NULL if not returned) |
| status | VARCHAR(20) | issued / returned |
| fine | DECIMAL(10,2) | Fine charged (₹5 per overdue day) |
| created_at | DATETIME | Creation time |

## 5.4 Data Flow Summary

1. Login form → `Auth::login()` → verify against `users` → start session.
2. Book form → `Books::create()/edit()` → validate → save to `books`.
3. Issue form → `Issues::issue()` → decrement `available_copies` → insert `issues`.
4. Return → `Issues::return_book()` → increment `available_copies` → update `issues`.
5. Dashboard → models aggregate counts → views render cards, charts and tables.
