# 4. SYSTEM ANALYSIS

## 4.1 Existing System

In a typical manual library, the following activities are performed on paper:

- Books are entered into an accession register.
- Members fill application forms stored in files.
- Every issue and return is written by hand in a day register.
- Overdue tracking requires manually checking each entry against the calendar.
- Fines are calculated by hand and disputes are common.

### 4.1.1 Limitations of the Existing System

| Limitation | Impact |
| --- | --- |
| Time consuming | Every transaction takes time to locate and write the correct record. |
| Prone to errors | Handwritten entries can be misread or skipped. |
| No instant availability | It is hard to know how many copies of a book are currently free. |
| No overdue tracking | Late returns are noticed only when a member visits. |
| No reports | Statistics (issued, returned, overdue) require manual counting. |
| No backup | Paper registers can be damaged or lost. |

## 4.2 Proposed System

The proposed system is a web application that replaces the registers:

- A central **database** stores all records consistently.
- **Login security** ensures only the librarian can use the system.
- **Books, categories and members** are managed through simple forms.
- **Issuing and returning** books are one-click operations that update copy counts automatically.
- **Overdue reports** are generated automatically based on the due date.
- **Fines** are computed automatically (₹5 per day).
- A **dashboard** gives an instant summary using cards, tables and charts.

### 4.2.1 Advantages

1. Fast and accurate transaction recording.
2. Instant availability of any book.
3. Automatic overdue and fine calculation.
4. Complete issue history available any time.
5. Professional, responsive and themeable user interface.
6. Portable — the default SQLite database needs no server setup.

## 4.4 Requirements

### 4.4.1 Hardware Requirements

| Component | Minimum |
| --- | --- |
| Processor | Any modern x86/x64 processor |
| RAM | 2 GB (4 GB recommended) |
| Disk | 500 MB free space |
| Display | 1024×768 or higher |

### 4.4.2 Software Requirements

| Software | Purpose |
| --- | --- |
| Windows 10/11 (or Linux/macOS) | Operating system |
| PHP 8.x | Server-side runtime |
| Web browser (Chrome/Edge/Firefox) | Client |
| Node.js + npm | Building CSS/JS bundles |
| Composer (optional) | Installing BladeOne if `vendor/` is absent |

### 4.4.3 Functional Requirements

1. The system shall allow the librarian to log in and log out.
2. The system shall allow adding, editing, deleting and searching books.
3. The system shall allow adding, editing and deleting categories.
4. The system shall allow adding, editing, deleting and searching members.
5. The system shall allow issuing a book to a member with a due date.
6. The system shall allow returning a book and updating copy counts.
7. The system shall list currently issued books and overdue books.
8. The system shall compute fines for overdue returns.
9. The system shall show a dashboard with statistics and charts.
10. The system shall provide a CLI migration mechanism for the database schema.

### 4.4.4 Non-Functional Requirements

- **Security:** password is stored hashed (`password_hash`); protected pages redirect unauthenticated users to the login page.
- **Usability:** consistent TailAdmin design, clear forms, confirmations before delete.
- **Responsiveness:** layout adapts to mobile, tablet and desktop widths.
- **Maintainability:** MVC separation of models, views and controllers; template partials for layout.
- **Performance:** lightweight framework and locally bundled assets keep pages fast.
