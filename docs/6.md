## 6.3 Key Implementations

### 6.3.1 Authentication (Auth controller)

The `Auth` controller verifies the username and password against the `users` table. Passwords are stored with `password_hash()` and verified with `password_verify()`. On success the user data is stored in the session; all other controllers extend `App_Controller`, which redirects unauthenticated visitors to the login page.

```php
if ($user) {
    $this->session->set_userdata('user', array(
        'id'       => $user->id,
        'username' => $user->username,
        'name'     => $user->name,
    ));
    redirect('dashboard');
}
```

### 6.3.2 Dashboard (Dashboard controller)

The dashboard aggregates statistics: total books, total copies, available copies, members, categories, issued, returned, overdue, issues-per-month and books-per-category.

```php
list($total_copies, $available_copies) = $this->Book_model->sum_copies();
$monthly = $this->Issue_model->count_by_month();
```

The view renders four metric cards, an **Issues by Month** bar chart (`#chartOne`), a **Collection Status** radial gauge (`#chartTwo`), **Top Categories** progress bars and a **Recent Issues** table. Chart data is passed through HTML `data-*` attributes and initialised by the standalone `assets/js/dashboard.js` file.

### 6.3.3 Books / Categories / Members CRUD

Each module follows the same pattern:

- `index()` lists records with optional search.
- `create()` / `edit()` render a form; `_form()` handles POST validation and save.
- `delete()` removes the record after a confirmation.

Book issuing and returning update the copy counts so a book cannot be issued when `available_copies` is zero.

### 6.3.4 Issue and Return (Issues controller)

```php
// Issue: reduce available copies and insert the record
$this->Book_model->adjust_copies($book_id, -1);
$this->Issue_model->issue(array(
    'book_id'    => $book_id,
    'member_id'  => $member_id,
    'issue_date' => date('Y-m-d'),
    'due_date'   => $due_date,
    'status'     => 'issued',
));

// Return: restore the copy and update the record
$this->Book_model->adjust_copies($book_id, +1);
$this->Issue_model->return_book($id, array(
    'status'      => 'returned',
    'return_date' => date('Y-m-d'),
    'fine'        => $fine,
));
```

The overdue list is computed as `status = 'issued' AND due_date < today`, and the estimated fine on the overdue page is `days_late × ₹5`.

### 6.3.5 User Interface (TailAdmin Design)

- **Login page** — split layout: a form panel on the left and a branded dark panel with the grid decoration on the right; includes a floating theme toggle.
- **Admin layout** — collapsible sidebar (290px/90px) with icons, sticky header with search, notifications, user menu and theme toggle; a page preloader and dark-mode flash-prevention script.
- **Content pages** — card containers, TailAdmin tables, pills/badges and form controls all include `dark:` variants.

### 6.3.7 Database Migrations (CLI)

Schema is versioned in `application/migrations/`:

| File | Table |
| --- | --- |
| 001_create_users.php | users (+ default admin seed) |
| 002_create_categories.php | categories |
| 003_create_books.php | books |
| 004_create_members.php | members |
| 005_create_issues.php | issues |

Commands:

```bash
php index.php migrate            # migrate to the latest version
php index.php migrate version 3  # migrate up/down to a specific version
```

The `Migrate` controller is CLI-only (`is_cli()` guard) and uses `dbforge` to create/drop tables.
